# Learning Cards

Four layers per card: **L0** a twelve-year-old can follow → **L1** the mechanism → **L2** how to use it → **limit** when it fails. Gap evidence follows each cluster.

## c18 断点与恢复（4 件）— 证据：`agent checkpoint resume` 225 仓半满但对口少；HN 亲测痛点：checkpoint 缺意图与计划，冷启动恢复不了；NVIDIA flare：分支后状态完整性

- **L68 冷启动恢复测试**：L0 检查"存档"够不够新来的人用：只看存档，一个全新的伙伴能不能接上活？接不上就是坏存档。L1 用空白上下文只读 checkpoint 尝试复述：目标/已完成/下一步/约束，四项复述不出 → 判存档不合格。L2 断言=①四项齐判 PASS、②缺「下一步」判 FAIL。
- **L69 状态完整性断言**：L0 恢复现场后先点数：该在的东西都在吗？对话、变量、中间结果，缺一样就别急着跑。L1 恢复后对照执行前快照逐项断言（键集合+值类型），输出缺失清单。L2 断言=①缺键报缺、②全齐报 PASS。
- **L70 恢复成本估计**：L0 断点不是免费的：它算一算"从存档接着干"要重新付多少（重读文件、重建上下文），再决定值不值得断。L1 估计重算 token/时间 vs 存档大小，给「断/不断」建议。L2 断言=①重算成本>存档收益时建议不断、②反之建议断。
- **L71 断点新鲜度**：L0 存档放久了会过期：代码改了、依赖换了，老存档接着用会翻车。L1 对 checkpoint 记录环境指纹（依赖版本/文件哈希），恢复时比对，不一致 → 先升级存档再恢复。L2 断言=①指纹不一致拦截、②一致放行。
